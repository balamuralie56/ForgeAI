# Changelog — v0.9.5

## [0.9.5] — 2026-08-28

### Added

#### Security Plugin (`forge_plugins/security/`)
- **`plugin.py` / `service.py`**: `SecurityService` contract and implementation, tied into the Kernel's plugin lifecycle alongside Planner, Architect, Developer, Tester, Documentation, and Git.
- **AST-based static analysis (`rules/`)**: Eight rules registered against a shared `SecurityRule` base — `SEC-001-EVAL`, `SEC-002-EXEC`, `SEC-003-SHELL`, `SEC-004-PICKLE`, `SEC-005-WEAKCRYPTO`, `SEC-006-HARDCODED`, `SEC-007-SQL`, `SEC-008-TEMPFILE` — each carrying a CWE id, OWASP category, severity, and remediation text.
- **`components/static_analyzer.py`**: Walks the target workspace's AST, applying every enabled rule per file.
- **`components/secret_scanner.py`**: Pattern-based secret detection independent of the AST rules (catches secrets in non-Python files).
- **`components/vulnerability_scanner.py`**: Checks `requirements.txt` dependencies against known CVEs.
- **`components/license_checker.py`**: Flags copyleft-licensed dependencies that could conflict with project licensing.
- **`components/ignore_engine.py`**: `.forgeignore`-style exclusion so generated/vendored code doesn't get scanned.
- **`components/report_generator.py`**: Emits Markdown, JSON, and industry-standard SARIF reports.
- **`writers/security_writer.py`**: Atomic report writes with rollback on failure, matching the pattern used by the Documentation and Developer plugins.
- **`validators/security_validator.py`**: Release quality gates — blocks the Git plugin's commit/release step when critical/high finding counts or the overall risk score exceed configured thresholds (`security.max_critical`, `security.max_high`, `security.max_risk_score`).
- **`utils/security_pipeline.py`**: Coordinates scan → analyze → report → gate as a single pipeline step, wired into the Workflow Orchestrator's `SECURITY` stage.

#### Configuration
- **`config/defaults.json`**: New `security` block — `enabled`, `secret_scan`, `dependency_scan`, `ast_scan`, `license_scan`, `llm_review`, `block_release`, `max_risk_score`, `max_high`, `max_critical`, and a `rules` map to toggle individual rule ids.
- **`FORGE_GITHUB_TOKEN` environment override**: The Git plugin's GitHub PAT can now be supplied via environment variable instead of only `forge.json`, keeping the secret out of any file on disk in CI/deployment contexts.

#### Tests
- **`forge_tests/test_security.py`**: Full unit/integration coverage for every rule, the scanners, report generation, ignore handling, and the release-blocking quality gate.
- **`forge_tests/test_config_manager.py`**: Added coverage for the new `FORGE_GITHUB_TOKEN` override precedence.

### Fixed
- Removed dead-code fallback branches in `hardcoded_password_rule.py`, `shell_rule.py`, and `weak_crypto_rule.py` that matched on `ast.Str` / `ast.NameConstant` — node types Python's parser has not produced since 3.8, and which the `ast` module fully removes in 3.14. The two tests that existed solely to hand-construct those deprecated nodes were removed with them; the modern `ast.Constant` path already covers every case a real parse can produce.
- Cleaned up a corrupted, triple-duplicated `.gitignore` (stray encoding artifacts had turned one entry into `.DS_Storet e s t _ l o g s /`).

## [0.9.5] — 2026-08-28 (Reviewer Plugin)

### Added

#### Reviewer Plugin (`forge_plugins/reviewer/`)
- **`plugin.py` / `service.py`**: `ReviewerService` contract and implementation, auto-discovered by the standard `PluginManager` (added `"reviewer"` to `plugins.enabled_plugins`) — unlike Workflow, it needed no special-case Kernel wiring.
- **10 AST code-quality rules (`rules/`)**: `REV-001-LONGFUNC`, `REV-002-TOOMANYPARAMS`, `REV-003-GODCLASS` (SRP), `REV-004-DEEPNESTING`, `REV-005-MAGICNUMBER`, `REV-006-NODOCSTRING`, `REV-007-MUTABLEDEFAULT`, `REV-008-TYPECHECKCHAIN` (OCP), `REV-009-FATINTERFACE` (ISP), `REV-010-CONCRETEDEP` (DIP).
- **`components/solid_scorer.py`**: Derives a 0-100 score per SOLID principle from the findings tagged with that principle. **Liskov Substitution ("L") is always reported as `None`** (not evaluated) — detecting it correctly needs cross-class contract analysis (does an override honor the base class's pre/post-conditions?), which this plugin's per-AST-node rule interface has no way to see. Reported as a known limitation rather than shipping a rule that would misfire constantly.
- **`components/static_analyzer.py` / `components/analyzer_factory.py`**: Mirrors the Security plugin's scanner shape; reuses `SecurityIgnoreEngine` directly since it's a generic path-exclusion utility with no security-specific behavior.
- **`components/report_generator.py`**: Markdown + JSON report with a quality score, per-principle SOLID breakdown, and optional LLM-authored review notes.
- **`utils/reviewer_pipeline.py`**: Single-scanner pipeline (no DAG needed — Security's 4-scanner concurrent pipeline was overkill for Reviewer's one AST pass).
- **`writers/reviewer_writer.py`**: Writes `review_report.json`, `review_summary.md`, `review_manifest.json` to the workspace.
- **Own quality gate**: `reviewer.block_release` + `reviewer.min_quality_score` in `config/defaults.json`, checked inside `review_project()` itself — no changes needed to the Git plugin's validator.

#### Workflow Orchestrator integration
- Added a `"reviewer"` stage to `FULL_ENGINEERING`, running after `security` and before `git` (optional, non-critical — same posture as `security` and `documentation`). `review_report` flows through `workflow.context` the same way `security_report` does.

#### Tests
- **`forge_tests/test_reviewer.py`**: 41 tests covering every rule (positive and negative cases), the SOLID scorer, report generator, validator, writer, full service integration, the quality gate, and plugin registration.
- **`forge_tests/test_workflow_orchestrator.py`**: Updated the full-engineering E2E test for the new 8-stage pipeline (was 7).

### Fixed
- `forge_plugins/reviewer/components/solid_scorer.py` had a real bug caught by its own test suite: `scores[p] or 100.0` treated a legitimately-computed `0.0` score as falsy and reset it back to 100.0 on the next penalty, so a principle could never actually stay floored at zero. Fixed by tracking the running score in a plain `Dict[str, float]` and only converting to `Optional[float]` in the final result.

### Verified
- Dogfooded against ForgeAI's own real source (excluding test fixtures/venv/generated workspace): 391 findings, dominated by missing docstrings (INFO) and a handful of genuine long-function/concrete-dependency findings — no false-positive spam, no crashes.
- 278/278 tests pass, 92% coverage (gate 90%), `black`/`ruff`/`mypy` all clean.
- `forge_core/version.py` bumped to 0.9.5.
